# WSB WhatsApp Bot 网站生成器

## Problem Statement

顾客需要一种快速方式来获得简单的实时数据网站（如飞机票价格），但不想自己写代码或找开发者。现有的 WSB WhatsApp bot 已经有 AI 对话能力，可以扩展为接收需求描述、自动生成网站代码并部署到公网的工具。服务器资源有限，最多同时 host 2 个网站，旧的自动清除。

## Context

- **WSB Bot**: Node.js WhatsApp bot，使用 `whatsapp-web.js`，已有 AI 能力（OpenRouter API）
- **服务器**: AWS EC2，公网 IP `18.141.191.212`，pm2 管理进程
- **AI**: 通过 OpenRouter 调用免费模型，有 fallback 链
- **现有命令**: `!news`, `!tech`, `!car`, `!property`, `!rank`, `!help` 等
- **端口 8080**: 目前未被占用，可用于网站服务

## Chosen Approach

**Express 静态服务器 + AI 单文件生成**

- 新增 `!website <描述>` 命令到 WSB bot
- AI 通过 OpenRouter 生成完整的单文件 `index.html`（内嵌 CSS/JS）
- AI 自行搜索并集成合适的免费公开 API 作为数据源
- 独立 Express 进程 serve 静态文件，监听 8080 端口
- 最多 2 个网站槽位，超出时自动删除最旧的
- 白名单控制谁可以使用此功能

## Why This Approach

**选择理由：**
- 纯静态 HTML：最简单的部署方式，无需后端运行时
- 单文件生成：减少 AI 输出复杂度，避免多文件协调问题
- Express 静态服务器：不需要额外安装 nginx，与现有 Node.js 生态一致
- 2 个槽位限制：保护服务器资源，简化管理

**拒绝的方案：**
- Nginx 反代：需要额外安装和配置，增加复杂度，当前阶段过度设计
- 模板系统：限制了灵活性，AI 直接生成更通用
- Node.js 全栈：对于实时数据展示，前端直调 API 已足够

## Design

### 1. 命令处理器 (`website-builder.js`)

**职责：** 接收 WhatsApp 消息、调用 AI 生成代码、管理文件系统

**流程：**
1. 收到 `!website <描述>` 消息
2. 检查发送者是否在白名单中
3. 从描述生成 URL-safe slug（AI 或简单的拼音/时间戳）
4. 构造 system prompt，要求 AI 生成单文件 HTML
5. 调用 OpenRouter API 生成代码
6. 提取 HTML 内容（去除 markdown 代码块包裹）
7. 检查当前网站数量，超过 2 个则删除最旧的
8. 写入 `/home/chin/websites/active/<slug>/index.html`
9. 返回访问 URL

**AI System Prompt 要点：**
- 生成完整的单文件 `index.html`
- 内嵌所有 CSS 和 JavaScript
- 可以使用 CDN 引入前端库（Tailwind CSS、Chart.js 等）
- 自行选择合适的免费公开 API 作为数据源
- 页面必须有自动刷新或定时更新机制
- 输出纯 HTML，不要 markdown 包裹
- 页面要美观、移动端友好

**新增命令：**
- `!website <描述>` — 生成并部署网站
- `!websites` — 列出当前活跃的网站
- `!delsite <slug>` — 手动删除指定网站

### 2. 静态服务器 (`website-server.js`)

**职责：** 独立 Express 进程，serve 静态文件

- 监听端口 8080
- Serve `/home/chin/websites/active/` 目录
- 每个子目录是一个网站
- 根路径 `/` 显示简单的网站列表页
- pm2 管理，开机自启

### 3. 白名单 (`config.js` 扩展)

在 `config.js` 中新增：
```
websiteWhitelist: ['60xxxxxxxxx@c.us']
```

只有白名单中的号码可以使用 `!website` 命令。

### 4. 网站槽位管理

- 目录结构：`/home/chin/websites/active/<slug>/index.html`
- 元数据文件：`/home/chin/websites/meta.json`，记录每个网站的创建时间、描述、创建者
- 最多 2 个活跃网站
- 新建第 3 个时，自动删除最旧的（按创建时间）
- 删除时清理目录和元数据

### 5. 数据流

```
WhatsApp 消息
  → index.js (命令路由)
    → website-builder.js
      → ai.js (OpenRouter API 调用)
        → 生成 HTML
      → 文件系统 (写入 /websites/active/<slug>/)
      → meta.json (更新元数据)
    → 回复 URL 给顾客

Express 静态服务器 (独立进程)
  → serve /websites/active/ 目录
  → 顾客通过浏览器访问
```

### 6. 错误处理

- AI 生成失败：回退到下一个模型（已有机制），全部失败则告知用户
- 生成内容不是有效 HTML：简单校验（检查 `<html>` 或 `<!DOCTYPE>`），无效则要求 AI 重试一次
- 文件写入失败：报错给用户
- 端口被占用：启动时检测并提示

## Open Questions

- OpenRouter 免费模型的 `max_tokens: 2048` 对于生成完整网站可能不够，可能需要提高到 4096 或更多
- 如果 AI 生成的 HTML 引用了需要 CORS 的 API，前端直调可能被拒绝——这种情况需要后续观察
- 是否需要给生成的网站加一个简单的 footer 标识（如 "Generated by WSB Bot"）

## Out of Scope

- HTTPS / SSL 证书
- 自定义域名
- 用户认证/登录系统
- 网站编辑/修改功能（只能重新生成）
- 多页面网站
- 后端 API 代理
- 数据库存储
